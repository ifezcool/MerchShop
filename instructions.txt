# Task: Replace fake eBay scraper with real eBay Browse API integration

**File to rewrite:** `scrapers/ebay_scraper.py`
**Files to touch:** `config.py`, `.env.example`, `services/search_service.py` (no schema change, just verify), `requirements.txt`

## Context (read this first)

`ebay_scraper.py` currently does NOT call eBay. It generates fake, templated
product titles/prices/ratings and builds a plain eBay search URL from that
fake title. There is no real product data. This task replaces that with real
results from eBay's **Browse API**, using an **Application access token**
(client credentials grant — no user login required, this is store-side
product search, not account-specific).

Do not touch `amazon_scraper.py` or `aliexpress_scraper.py` in this task —
same fake-data problem exists there but is out of scope.

## 1. Prerequisites (human must do this manually first — flag if missing)

1. Create an eBay Developer account: https://developer.ebay.com
2. Create an application under "Application Keys" → get a **Production**
   `Client ID` (App ID) and `Client Secret` (Cert ID).
3. No redirect URI / RuName needed for this flow — client credentials grant
   is app-only, not user OAuth.

If `EBAY_CLIENT_ID` / `EBAY_CLIENT_SECRET` are not present in the
environment, the scraper must fail gracefully (return `[]` and log a clear
warning), not crash the app.

## 2. Config changes

In `config.py`, add:

```python
EBAY_CLIENT_ID = os.getenv("EBAY_CLIENT_ID", "")
EBAY_CLIENT_SECRET = os.getenv("EBAY_CLIENT_SECRET", "")
EBAY_MARKETPLACE_ID = os.getenv("EBAY_MARKETPLACE_ID", "EBAY_US")
```

Add the same three keys (blank values) to `.env.example` with a comment
explaining where to get them.

## 3. New OAuth token handling

Client credentials grant (app token, NOT the PKCE user-login flow already
used for MAL — do not reuse or confuse the two):

- `POST https://api.ebay.com/identity/v1/oauth2/token`
- Header: `Authorization: Basic <base64(client_id:client_secret)>`
- Header: `Content-Type: application/x-www-form-urlencoded`
- Body: `grant_type=client_credentials&scope=https://api.ebay.com/oauth/api_scope`
- Response: `{ "access_token": "...", "expires_in": 7200, ... }`

Requirements for the implementation:
- Cache the token in memory with its expiry timestamp; only refetch when
  expired (don't request a new token on every search call).
- If the token request fails, log the status code + response body and
  return `[]` from `search()` — never raise up into the Streamlit UI.

## 4. Real search call

- `GET https://api.ebay.com/buy/browse/v1/item_summary/search`
- Header: `Authorization: Bearer <access_token>`
- Header: `X-EBAY-C-MARKETPLACE-ID: EBAY_US` (from `EBAY_MARKETPLACE_ID`)
- Query params: `q=<search query>&limit=10` (add `category_ids` later if
  needed; not required for v1)

Relevant response fields per item in `itemSummaries[]`:
- `title`
- `price.value`, `price.currency`
- `image.imageUrl` — this is a **real product photo**, use it directly
- `itemWebUrl` — this is the **direct link to the exact listing** (this is
  the fix for "leads to search rather than the exact item")
- `itemId`
- optional: `seller.feedbackPercentage` if you want a rating-like field

## 5. Rewrite `EbayScraper.search()`

Keep the exact same return schema the rest of the app expects (see
`base_scraper.py` / other scrapers for the dict shape: `id`, `title`,
`price`, `currency`, `url`, `image_url`, `store`, `product_type`,
`anime_title`, `rating`). Map real API fields into that shape:

```python
{
    "id": item["itemId"],
    "title": item["title"],
    "price": float(item["price"]["value"]),
    "currency": item["price"]["currency"],
    "url": item["itemWebUrl"],          # real item link, not a search URL
    "image_url": item.get("image", {}).get("imageUrl", ""),
    "store": "eBay",
    "product_type": product_type,
    "anime_title": anime_title,
    "rating": item.get("seller", {}).get("feedbackPercentage"),
}
```

Delete the hardcoded `templates` dict and the fake title generation
entirely. Build the search query from the real `query`/`anime_title`/
`product_type` args passed in (same as before), not from AniList character
names — those were only needed to make fake titles look specific.

Keep `self.rate_limiter.wait("ebay")` before the HTTP call.

Wrap the search HTTP call in try/except; on any exception or non-200
response, log it and return `[]` (matches existing silent-degrade pattern
elsewhere in the app, but log instead of bare `pass` so failures are
visible in server logs).
